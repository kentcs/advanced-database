Chapter 17: MongoDB Aggregation Pipelines

From IMDb Documents to a Yearly Ratings Summary

A database-backed page should not download millions of documents just to filter and summarize them. Let MongoDB perform the filtering, joining, grouping, and computation near the data. Send the small result to the client. Every client can submit the same pipeline instead of repeating the computation over raw records. Python sends the request through PyMongo; Streamlit presents the answer.

Our question is: For each release year, what is the mean IMDb rating of movies with at least 1,000 votes? We will use 1990–1999, inclusive. A year with no qualifying movies has no row. This is a description of a filtered sample, not a claim that movies improved or declined over time.

By the end, you should be able to trace a document through a pipeline, explain which movies enter an average, and connect the server result to a Streamlit page. Allow about 20–25 minutes, including the live demonstration.

Start with the data we already imported

Chapter 16 imports the IMDb data with the Chapter 14 importer. It uses these fields, not the original TSV camelCase column names:

Collection Fields used here Meaning
titles _id, title_type, start_year IMDb identifier, kind of title, integer release year
ratings _id, average_rating, num_votes Same identifier, numeric rating, integer vote count

Missing imported numeric values are null. The collections are separate: average_rating is not a field on titles. Matching _id values connect them. Chapter 16’s search page looked up ratings in Python; this page joins them on the server. An existing _id index supports the lookup.

A pipeline is an ordered sequence of transformations

Each stage receives documents from the previous stage. The collection is the input; the final documents are the result. Our pipeline uses seven stages:

Stage What comes out
$match Movies whose release year is in the chosen range
$lookup Each movie plus a rating array of matching rating documents
$unwind One document per matched rating; unrated titles disappear
$match Movies meeting the vote threshold and having a numeric rating
$group One summary document for each year
$sort Summaries in ascending year order
$project Clearly named output fields, with the mean rounded for display

These stages run inside MongoDB. They do not change the stored documents.

Filter, then join the ratings

Here is the beginning of the pipeline, as a Python list of dictionaries sent to MongoDB. The example uses fixed values; the runnable helper accepts form values.

pipeline = [
    {"$match": {"title_type": "movie",
                "start_year": {"$gte": 1990, "$lte": 1999}}},
    {"$lookup": {"from": "ratings", "localField": "_id",
                 "foreignField": "_id", "as": "rating"}},
    {"$unwind": "$rating"},
    {"$match": {"rating.num_votes": {"$gte": 1000},
                "rating.average_rating": {"$type": "number"}}},
]

Filtering early reduces the movies reaching the join. The first stage may use the existing (title_type, start_year) index; check rather than assume it is present. An equality lookup produces an array, even when _id makes the match unique. $unwind turns that one-element array into a rating object. Its default behavior drops empty arrays, so movies without a rating do not enter the summary. The second match removes low-vote ratings and nonnumeric values before counting.

Group, sort, and name the answer

Append these stages to the list above:

pipeline += [
    {"$group": {"_id": "$start_year",
                "rated_movies": {"$sum": 1},
                "mean_rating": {"$avg": "$rating.average_rating"},
                "total_votes": {"$sum": "$rating.num_votes"}}},
    {"$sort": {"_id": 1}},
    {"$project": {"_id": 0, "year": "$_id", "rated_movies": 1,
                  "mean_rating": {"$round": ["$mean_rating", 2]},
                  "total_votes": 1}},
]

In $group, _id is the group key: the year, not the movie identifier. $sum: 1 counts qualifying movies. $avg averages their title-level ratings. $sum over votes describes the sample’s total votes. $group does not promise an output order; $sort makes the table predictable. $project renames the year, removes _id, keeps the counts, and rounds only the final mean.

Each movie has equal weight in mean_rating. It is not a vote-weighted average and is not the mean of individual users’ votes. Raising the threshold changes which movies qualify; it does not give high-vote movies extra weight.

Trace a tiny example before using the full dataset

These are invented fixture records, not measured IMDb results:

Movie Year Rating Votes
A 1990 8.0 2,000
B 1990 6.0 1,000
C 1991 9.0 500
D 1991 7.5 1,500
E 1991 no rating document —

At a 1,000-vote threshold, C fails the vote test and E disappears at $unwind. The result is:

year rated_movies mean_rating total_votes
1990 2 7.0 3,000
1991 1 7.5 1,500

Predict the result at 1,500 votes before running it: 1990 has one movie rated 8.0 with 2,000 votes; 1991 is unchanged. This checks the meaning of the pipeline, not just whether it runs.

Submit the pipeline; display its result

code/aggregation_queries.py holds the shared pipeline builder. Both the command line and Streamlit use it, so the lecture and dashboard run the same query.

from aggregation_queries import connect, build_pipeline, summarize

client, db = connect()
try:
    rows = summarize(db, build_pipeline(1990, 1999, 1000))
finally:
    client.close()

The helper’s database operation is:

rows = list(db.titles.aggregate(
    pipeline, maxTimeMS=30000, allowDiskUse=True))

Only the summary rows cross into Python. allowDiskUse permits temporary disk work if needed; it does not make a large query instant. The 30-second limit bounds the classroom demo. A timeout means try a narrower year range and inspect indexes; it does not mean no movies matched.

The Streamlit page adds a form for the two years and vote threshold, shows the actual pipeline, and displays the returned rows:

frame = pd.DataFrame(rows)[
    ["year", "rated_movies", "mean_rating", "total_votes"]]
st.dataframe(frame, hide_index=True)
st.bar_chart(frame, x="year", y="mean_rating")

There is no second aggregation in Pandas. The page handles an empty result, reversed years, and a failed connection. Connection errors do not display the credential-bearing URI. See the run guide for setup and commands.

Teach it in one pass

  1. 3 minutes: Explain server computation versus transferring raw data.
  2. 4 minutes: Check the two collections and trace the join.
  3. 6 minutes: Build the stages and predict the fixture result.
  4. 7 minutes: Run the CLI, then the Streamlit page over Chapter 16 data.
  5. 3 minutes: Raise the vote threshold and explain the changed sample.

Exit question: Why must the vote filter run before $group? Answer: we want only qualifying movies contributing to both the count and the mean; after grouping, the individual rating and vote fields no longer exist.
